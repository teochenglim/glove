### v0.10.0 — Goose: first-class enforcement adapter (ready, untagged)

The ninth declared agent and seventh enforced one landed as the cleanest adapter in the matrix: goose (aaif-goose) ships a native **blocking** `PreToolUse` hook, so glove registers a pure Go adapter through a plugin manifest at `~/.agents/plugins/glove/hooks/hooks.json` — no shim, no proxy. The fail-closed posture the vendor offers is taken: the manifest carries `on_failure: "block"` and a `timeout` tightened to 15s, so a hung or crashed glove hook **blocks** the tool call (strictly stronger than codex/gemini/cursor), doctor flags a manifest that lost it, and the manifest is golden-pinned plus grammar-walked (goose skips a plugin's whole manifest on invalid values). Review renders as deny — goose hooks are allow/block only, the tighten-only rule applied and documented loudly. goose's built-in `shell` tool joined the engine's chain-splitting set (tighten-only), `write`/`edit` paths hit the protected globs, MCP tool args are scanned, and audit records carry `agent: "goose"` with ATT&CK tags and session correlation out of the box. The conformance harness now shares its body so goose passes the identical phases behind the §5.1 interface unchanged from 0.1.0; README matrix machine-verified at 7 enforced + zed audit. The open subagent question closed: subagent tool calls ride the same dispatch path (only the lifecycle events are never emitted). `make check` + `make race` + `make stress` + `make audit` + `GOOS=windows go vet` green; no new dependencies; fresh-HOME goose flow measured 0.72s against the 2-minute budget. Slots before the 1.0.0 freeze by design.

### v0.8.0 — Correlation + fleet: from records to signals (ready, untagged)

The audit trail started speaking in aggregate. Session escalation correlation derives state from the audit trail itself (keyed by `session_id`, bounded tail scans, no daemon): a session that has already accumulated block/review decisions tightens subsequent *undecidable* calls — nothing fired, verdict still allow — to review, with the tighten-only invariant extended and pinned (`TestAC_0_8_1_correlation_never_loosens`: deterministic blocks stay exit 2, deterministic reviews stay reviews, the correlation reason never attaches to a decided call). `[correlation] session_threshold` is policy-configurable (0 = default 3, -1 = disabled). `glove audit stats` gives the local SIEM-lite view — top rules/techniques/agents/decision counts over `--since` — with two honesty fixes found in the live transcript: a rule firing twice in one record counts once per record, and engine non-rule reasons never appear as phantom rules; the 10k load+aggregate ≤ 200ms gate lives in `make stress`. Policy bundles close the fleet story without a service: `policy pack` seals the exact policy bytes + origin metadata under one SHA-256 over both, `policy import` verifies before any write (tampered bundles leave the destination untouched, no event), shows the install diff, and emits the `policy_import` audit event with the checksum. An unreadable correlation trail degrades to "no escalation" — correlation is additive and has no decision of its own to protect (failure-modes section). `make check` + `make race` + `make stress` + `make audit` + `GOOS=windows go vet` green; no new dependencies.

### v0.7.0 — SIEM-ready: tamper-evident audit + forwarding (ready, untagged)

The audit trail became evidence a SIEM can trust and ingest, without touching the decision path. Every record is now chained (`prev_hash` → `record_hash`, schema version 2) so `glove audit verify` detects an edited, deleted, or truncated record across live and rotated files — the first surviving record anchors the chain, legacy pre-0.7.0 lines are skipped honestly, and the retention/tail-deletion limits are stated in `docs/siem.md`. Rules speak SIEM: all 16 builtin rules carry MITRE ATT&CK tags, user patterns tag via `[rules.techniques]`, records inherit the tags of every rule that fired, and `audit query --technique` filters on them. Records carry machine identity (`host`/`user`/`machine_id`) for fleet joins; `contract.Verdict` is untouched (§5.3 freeze green, pinned in both directions). `audit export --format cef|ecs` covers the ArcSight- and Elastic-class consumers. The outbound sink (file / syslog RFC 5424 / webhook) is post-decision, opt-in, off by default (ADR 4): bounded queue, one attempt, no retry, a drain window that counts unconfirmed deliveries as not delivered, and failures audited locally as `sink_error`/`sink_dropped` — a dead or stalling collector provably never changes a verdict, an exit code, or a latency budget. Malformed `[audit.sink]` config fails `policy validate` with source line numbers and fails the hook closed like any invalid policy. Found in the live transcript and fixed before shipping: the sink originally received the pre-write record (no timestamp, no chain) — `Writer.Write` now returns the stamped record, with a regression test. `make check` + `make race` + `make stress` + `GOOS=windows go vet` green; no new dependencies.

### v0.3.0 — Audit + Policy (tagged)

Every decision is now observable and tunable before intelligence lands. The audit log (`~/.local/share/glove/audit.jsonl`, 10 MB × 5 rotation) records every hook invocation with zero plaintext by default (SHA-256 input hash only; `--audit-verbose` adds redacted input) and answers `audit tail` / `audit query` / `audit export` in under 200ms on 10k records. The `policy.toml` engine (project > user > built-in; scalars override, pattern lists concatenate) extends hard-block/force-confirm/protected-path rules with nothing to restart — edits are enforced on the next tool call, and a change emits a `policy_reload` audit event. An invalid policy fails the hook closed with key-path errors (`policy validate` adds parser line numbers for syntax errors). This proves users can see and tune the Layer 0+1 false-positive rate in the wild before Laya arrives.
