# ADR 3: The Laya runtime is the laya-serve container

**Status:** accepted (2026-11-04, per the ROADMAP 0.4.0 probe mandate)

**Context.** PRD §7 0.4.0 needs semantic judgment ("Laya multilingual decision model, local CPU inference") behind `glove serve`. Two constraints collide: the binary is `CGO_ENABLED=0` (no libc surface, ≤ 15 MB — PRD §8), and production-grade pure-Go transformer inference for quantized GGUF models does not exist today (probed 2026-11: the viable pure-Go GGUF projects parse the format but none runs a modern multilingual decision model at usable quality/speed). Typical llama.cpp bindings all require cgo.

**Decision.** The probe resolved in favour of the runtime we already have: **Laya ships as a container** — `ghcr.io/teochenglim/laya` (english checkpoint) and `ghcr.io/teochenglim/laya:multilingual-cpu` (multilingual) — exposing `POST /v1/systemone` (TypeSafe Jev protocol: `choice`/`score`/`noul` questions about a text, one forward pass, tens of ms per head) and `GET /health`. Glove's binary carries **zero inference code**; the Laya runtime is an HTTP adapter:

1. **Contract**: serve (and only serve) talks to a laya-serve instance at a loopback endpoint — `--laya-endpoint` flag > `[laya] endpoint` policy > `http://127.0.0.1:8080`. Hook → serve is the only other hop (PRD §3.2).
2. **Questions**: the four typed questions map to `/v1/systemone` — `destructive`, `exfiltration`, `privilege_escalating` as `noul` (boolean) questions; `blast_radius` as a `choice` (local / system / remote). The command text rides in `state.message`; routing is the model's (multilingual checkpoint auto-detects script/language).
3. **Calibration** (tuned against the live container, 2026-11-04): only the `noul` flags block — `destructive`/`exfiltration`/`privilege_escalating` ≥ 0.6 → `block` (critical when destructive+exfiltration coincide or a flag coincides with a remote blast radius, else high). `blast_radius` is severity metadata, never a standalone block: the live model calls even `git status` "system-reaching" (answer_confidence 0.67). A reach verdict without flags → `review`; uncertainty (0.4–0.6 answers, or the policy `[laya] confidence_review_band` band) → `review`; else `allow`. The merged verdict always goes through `Combine` (§4.2 — Laya can only tighten).
4. **Distribution replaces download**: the PRD's first-run GGUF download + SHA-256 flow is replaced by the container image (docker pull *is* the distribution; the OCI digest *is* the checksum). `glove serve` prints the exact `docker run -p 8080:8080 ghcr.io/teochenglim/laya` setup line when the endpoint is down, prompts y/N to start it when docker is available and stdin is a TTY, and never auto-pulls silently. `[laya] image_digest` optionally pins the expected local image digest — a mismatch refuses to start (the AC0.4.5 verification, container-era).
5. **Fail-closed**: endpoint down, wrong service, timeout → `model_available: false` and the deterministic verdict stands, with undecidable allows escalated per `[general] on_model_unavailable` (PRD §3.2). Nothing ever degrades to an open gate.

**Consequences.** Single-binary distribution of the *guard* is intact; the model is operator-provisioned (one `docker run`). Wall-clock per 4-question call is ~0.5–2s warm on CPU — the PRD's 150ms/200ms budgets therefore gate the **serve-path overhead** (HTTP + calibration, CI-measured with a stub runtime), not model compute, and `[laya] hook_timeout_ms` (default 2000) bounds the hook's wait. The 150ms end-to-end number returns when the model runs on faster hardware/backends (the image's `gpu` tag exists). Prompt wording lives in `internal/server/laya_runtime.go` — model-behaviour changes (a better checkpoint) are container pulls, not glove releases.

**Alternatives considered.** Pure-Go GGUF inference (rejected: no production-grade runtime; building one is a product of its own); cgo llama.cpp (rejected: breaks the static-binary NFR); glove-managed GGUF download + sidecar llama-server (superseded: the laya container is the same architecture with the model packaged by its authors, digest-verifiable).
