## Built

Verified (2026-11-04, local macOS arm64, Go 1.27.3):
- `make check` + `make race` + `make audit` green; 35 enforced PRD bullets, 0 under-tested; six ACs with 2/3/2/2/2/4 named tests (`scripts/release-check.sh 0.6.0` green). No dependencies added.
- **CI matrix (AC0.6.1)**: `ci.yml` now runs ubuntu/amd64 + macos/arm64 with the full `make check` (carrying the §8 perf gates) and **windows/amd64 with build + vet + `go test -short`** (the timing benches stay off Windows runners — decided with the maintainer), plus a cross-compile job for darwin/amd64 + linux/arm64; push triggers include `main` so the green streak accrues between tags. The workflow is config-as-contract: `internal/release` parses it and fails `make check` if the matrix thins. All five §8 targets build statically (test-proven, ~10s).
- **Release pipeline (AC0.6.3)**: windows/amd64 joins the release artifacts (`.exe` inside the tarball); the publish job verifies every `.sha256` (`sha256sum -c`) **before** creating the release and aggregates `checksums.txt` (PRD §9). Signing is `scripts/sign-release.sh` — macOS codesign + `notarytool` notarization, Windows `signtool` Authenticode — env-gated for maintainer certificates, with checksum refresh after signing. The artifact+checksum pipeline is verified end-to-end locally (build → hash → aggregate → verify → corrupt-and-detect). PRD §7 amended: GoReleaser evaluated, the existing GH Actions flow retained (decision recorded).
- **Error-handling audit (AC0.6.2)**: `docs/failure-modes.md` — every failure path with its defined decision and the test that pins it, including the vendor-side fail-open surfaces and the "not a failure path" boundaries. The audit doc is config-as-contract too: cited test names must exist or `make check` fails. The live path is fuzzed: 13 corruption classes (empty/truncated/non-JSON/wrong-shape/null-bytes/mixed-scripts/1MB payload/5k-segment compound/…) × all seven agents → every case delivers a verdict, deny cases exit 2 with a stderr reason, corrupted policy denies closed, and an unwritable audit dir **never changes a delivered decision** (new pin: `TestAC_0_6_2_audit_write_failure_keeps_decision`).
- **Docs flows (AC0.6.4)**: every agent guide carries install/verify/uninstall with a ≤ 5 min time box; the documented flow runs through the real binary in a fresh HOME — two installs, doctor, hooks, uninstall — measured **0.73s wall** against the 5-minute budget.
- **Benchmarks + soak (AC0.6.5)**: `benchmarks/README.md` (repro instructions for every §8 claim) + `benchmarks/soak.sh` (mechanical soak; 60-iteration smoke: zero deviations); accelerated soak — 2,000 mixed in-process decisions with per-class exit-code checks and exactly one audit record per invocation, plus 50 real subprocess hooks — green.
- **Windows hardening (AC0.6.6)** — done only because CI now tests Windows: `%USERPROFILE%` / `%LOCALAPPDATA%` and backslash paths normalize in protected-path matching (`type %USERPROFILE%\.ssh\id_rsa` now blocks; expansion only adds candidates, so it only ever tightens); Windows audit/config/policy paths + per-agent paths resolve under `%USERPROFILE%` (test-built with `filepath.Join`, separator-agnostic). Fork overhead measured: **min 7.5 / median 8.0 / p95 9.1ms over 40 runs** (budget 15ms median), documented in `benchmarks/README.md`. Found during the work: `filepath.ToSlash` is a no-op on Unix — the normalization is string-level so behavior is identical on every OS.
- `docs/troubleshooting.md` added (PRD docs-completeness list); timing budgets scale under `-race` via a build-tagged constant (instrumentation invalidates wall-clock budgets; the un-instrumented `make check` keeps the real §8 budgets).

- The live-session smoke checks from v0.4.0/v0.5.0 remain pending the user (unchanged scope, not a 0.6.0 item).
