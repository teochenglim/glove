## Built

Verified (2026-11-05, local macOS arm64, Go 1.27.3): `make check` (42 active ACs, 48/50 enforced PRD bullets, 0 under-tested) + `make race` + `make stress` + `GOOS=windows go vet` green; `scripts/release-check.sh 0.7.0` green. No new dependencies.

- **ADR 4 first** (`docs/adr/0004-…`): recorded before any sink code, per the release guardrail — the invariant governs the decision, not the process; the sink is post-decision, opt-in, off by default, one attempt per record, bounded queue, and its failures are local-only audit events (never forwarded — no loop).
- **Hash chain (AC0.7.1)**: `schema_version` (2) + `prev_hash`/`record_hash` on every record — `record_hash` = SHA-256 over the record with `record_hash` zeroed (struct field order is the canonical form verify reproduces). The Writer initializes its chain from the on-disk tail and links across rotation boundaries; the mutex serializes writes so the chain is exact under concurrency (8-goroutine × 25-write test). `glove audit verify` walks the store (rotated `.N` → … → live), re-computes every hash and the linkage, names the first break (`edited` / `chain-gap` / `corrupt-line`) with file:line and audit_id, exits non-zero. Legacy (pre-0.7.0, schema-1) records are skipped as unchained, never a false alarm; the first surviving record's `prev_hash` is the anchor — retention-dropped files and tail deletion are the honestly-stated limits (docs/siem.md).
- **MITRE ATT&CK tags (AC0.7.2)**: all 16 builtin rules tagged (`mitre:` in builtin.yaml — T1485/T1561/T1499/T1548.003/T1565/T1222.002/T1059.004/T1552.00x); user patterns tag via `[rules.techniques]` (pattern → tag, merge-keyed across policy files, `policy validate` checks tag shape). The engine threads fired rule ids out of `EvaluateDetailed` (3rd return) and `Engine.TechniquesFor` maps them to deduplicated tags; the hook inherits them into the record; `audit query --technique` filters.
- **Machine identity (AC0.7.3)**: `host`/`user`/`machine_id` stamped by the Writer (single choke point — events get it too); `machine_id` = sha256(host+"/"+user)[:16], a stable join key derived from the other two. `contract.Verdict` untouched — `TestAC_0_7_3_contract_verdict_untouched` pins the negative direction (no audit-only field in the frozen JSON), the §5.3 freeze tests stay green.
- **CEF + ECS export (AC0.7.4)**: `audit export --format cef|ecs` — CEF with decision-mapped severity (allow 2 / review 5 / block 8, +2 critical), escaped header/extension values, `fileHash`/`cs1` session/`cs2` techniques/`cs3` machine_id extensions; ECS 8.11 documents with `event.outcome` (success/failure/unknown) plus the raw decision under `glove.*`. 100-record mixed fixtures (multilingual reasons, pipes/equals in text) assert both.
- **Sink (AC0.7.5/6)**: `internal/audit/sink.go` — bounded dispatcher (queue 256, Enqueue never blocks, drops counted), one delivery attempt, no retry; file / syslog (RFC 5424 with PRI per decision + `[glove@1]` structured data, udp|tcp|tcp+tls|unix) / webhook (http(s) POST of the record JSON). `Drain(timeout)` returns drop/failure counts; **on drain timeout the unconfirmed records are counted as not delivered** (the honest posture — the hook may be exiting). The hook dispatches strictly after the decision is rendered and the local line is written; drop/failure counts become local-only `sink_error`/`sink_dropped` events. `[audit.sink]` validates with source line numbers (`policy validate`); malformed config is invalid policy → hook fails closed (AC0.3.7's rule). `docs/failure-modes.md` gains the v0.7.0 failure table (contract-checked); `docs/siem.md` carries the ingestion recipes and the field mapping.
- **Found in the live transcript, fixed before shipping**: the first draft forwarded the caller's pre-write Record to the sink (zero timestamp, no identity, no chain). `Writer.Write` now returns the stamped record and the sink forwards exactly what the log holds — pinned by a regression subtest in `TestAC_0_7_5_sink_off_by_default`.
- Live transcript: hook block/review → `audit verify` ok → `query --technique T1548.003` hits → CEF/ECS lines correct → file sink receives the stamped record (schema 2, machine_id, chain, T1485).

Limits:
- The sink is exercised at the protocol level (RFC 5424 datagrams, HTTP POST, file appends) — not against a live Splunk/Elastic/ArcSight instance; tcp+tls syslog compiles and validates but only udp was exercised against a real listener.
- Tail deletion is undetectable by design (no forward anchor in an append-only log); near-real-time forwarding is the mitigation and is exactly what the sink provides.
- `serve /evaluate` does not forward — the hook process is the audit writer; the sink runs there (documented in docs/siem.md).
- Pre-existing (0.2-era) cosmetic: single-segment commands report their rule twice (raw pass + segment pass both fire) — visible in the transcript's doubled reason; decisions and tags are correct. Untouched in 0.7.0; note for a future polish patch.
- The live-session smoke checks and other external proofs remain with the user (unchanged scope).
