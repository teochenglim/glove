# RELEASE v0.9.1: fix the install-script CI fixture (patch)

**Status:** ready (tag pending)
**Patch gate:** test-fixture fix only, no AC change and no product change (RELEASE.md §3 versioning). Cause read from the failed v0.9.0 ubuntu run via the CI log.
**Depends on:** v0.9.0 (tagged)
**Requirements:** none new — the affected AC remains v0.9.0's (AC0.9.1)

## Built

- **`TestAC_0_9_1_install_script_checksum_verified` 404'd on ubuntu**: the fake release server hardcoded `darwin/arm64`, so on the linux/amd64 runner the install script correctly requested `glove-v0.9.0-linux-amd64.tar.gz` — which the fixture never served (curl 22 → 404), failing both the clean-install and tampered-checksums subtests before the checksum stage was ever reached. The fixture now serves `runtime.GOOS`/`runtime.GOARCH` (which map 1:1 onto the script's uname detection: linux|darwin × amd64|arm64), and the unlisted-asset subtest's checksums line is platform-derived too. Passed locally on darwin/arm64; the ubuntu lane is the real proof and gets it on the next tag push.
- En route: the `runtime` package name collides with `internal/cli`'s own `runtime` struct — aliased as `guntime`, the 0.6.1 precedent.

Verified (2026-11-05, local macOS arm64): `make check` green (48 active ACs, 50/50 enforced bullets, 0 under-tested).

## Limits

- The macos lane never caught this because the fixture matched the dev platform — the lesson is recorded in AGENTS.md pitfalls: platform-shaped test fixtures must derive the platform from `runtime`, never hardcode the dev machine's.
