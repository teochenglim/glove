# RELEASE v0.6.3: windows fixes that 0.6.2 actually needed (patch)

**Status:** ready (tagged — first release with **all four workflows green**: CI ubuntu, CI macos, CI windows, Release, Docker, Security)
**Patch gate:** fixes plus a trigger-discipline change, no AC change (RELEASE.md §3 versioning). Causes read from the failed v0.6.2 run via `gh`; the fixes were verified present in the tree before tagging (the 0.6.2 lesson).
**Depends on:** v0.6.2 (tagged)
**Requirements:** none new — the affected ACs remain v0.6.0's

## Built

- **`matrixTestEnv` sets `USERPROFILE` alongside `HOME`** — `os.UserHomeDir` reads `USERPROFILE` on Windows, and without it the in-process install/doctor/list tests landed glove's writes in the runner's real profile (the 0.6.2 write that never happened).
- **Golden shim compare normalizes both sides**: the CRLF came from the *rendered* shim — the `go:embed`'ed template is converted on a Windows checkout — while 0.6.2 normalized only the golden. The template is additionally pinned byte-stable in `.gitattributes` (`internal/adapter/templates/*.tmpl -text`).
- **Tags-only CI trigger (maintainer decision)**: a release push lands the commit on main AND the tag, and the workflow ran the identical matrix twice per release. CI now runs per release tag and on PRs only; the config-as-contract test asserts the discipline.

Verified (2026-11-04, local macOS arm64): `make check` + `make race` green; `GOOS=windows go vet` clean. CI after the tag push: ubuntu ✓ macos ✓ **windows ✓** — the windows lane passed for the first time, confirming the root causes were correctly identified.

## Limits

- The windows green was immediately followed by a policy decision: windows is removed from CI and the release matrix entirely (v0.6.4) — the fixes stand as proof the causes were understood; the removal is about value, not bugs.
