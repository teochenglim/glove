# RELEASE v0.10.1: fix the formula-version CI gate (patch)

**Status:** ready (tag pending)
**Patch gate:** one CI-gate fix, no AC change and no product change (RELEASE.md §3 versioning). Cause read from the failed v0.10.0 run (42321064255) via `gh` — both Check lanes red on the same test.
**Depends on:** v0.10.0 (tagged)
**Requirements:** none new — the affected AC remains v0.9.0's (AC0.9.1)

## Built

- **`TestAC_0_9_1_formula_matches_release_layout` was a per-release catch-22**: it required `formula version >= VERSION`, but the formula's version bump and sha256 fill land *around* the tag (the hashes can only be filled from the published `checksums.txt`), so every release where the formula legitimately lags one version failed both CI lanes — exactly what the v0.10.0 run did (`formula version 0.9.1 is older than VERSION (0.10.0)`). The rule is now the sustainable contract it meant to be: the formula may lag **at most one minor** behind VERSION (patch level ignored — the tap copy is refreshed per release); two or more minors behind means the formula stopped being maintained and fails `make check`. The formula itself is bumped to `version "0.10.0"` in the same change.
- Nothing else: no product code, no other tests touched. The naming/URL layout half of the test (the part that catches workflow renames) is unchanged.

Verified (2026-11-07, local macOS arm64): `make check` green (54 active ACs, 56/56 enforced bullets, 0 under-tested) + the fixed test green against both the current (formula == VERSION) and a one-minor-behind formula.

## Limits

- The ubuntu lane is the real confirmation — it gets the fix on the next tag push.
- The formula's sha256 lines for v0.10.0 are still filled post-tag via `scripts/update-homebrew-sha.sh 0.10.0` (packaging/homebrew/README.md step 2) — placeholder hashes refuse the install, the honest failure mode.
