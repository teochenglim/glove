# RELEASE v0.6.1: CI hardening fixes (patch)

**Status:** ready (tagged)
**Patch gate:** fixes only, no AC change (RELEASE.md §3 versioning). Causes were read from the failed v0.6.0 runs via `gh`; verification recorded below and in RELEASE.md §4/§5.
**Depends on:** v0.6.0 (tagged)
**Requirements:** none new — the affected ACs remain v0.6.0's

## Built

The v0.6.0 tag run failed three workflows (CI on main, CI on the tag, Release — Release's gate is the same `make check`). Four root causes, all fixed here:

- **`permission denied` on TempDir cleanup** (ubuntu, macos, and therefore the Release gate): the fresh-HOME flow and soak tests ran `go build` *after* overriding `HOME`, so the module cache landed inside `t.TempDir()` with read-only files. Builds now happen before the override — and got ~15× faster on cache reuse (`TestAC_0_6_4_fresh_home_flow_under_five_minutes`, `TestAC_0_6_5_soak_subprocess_stability`).
- **Shared-runner timing flakes**: compound-payload P95 35.6ms vs the 20ms budget (ubuntu); offline-fallback P95 21.3ms vs 5ms (macos). Both move to the house 50ms absorb-noise gate (the `TestAC_0_3_8` precedent); the strict budgets stay enforced by the in-process tripwires and remain the release-file numbers.
- **Windows portability (first windows runner run ever)**: `buildGlove` lacked the `.exe` suffix; the README coverage-matrix check was CRLF-sensitive; paths tests asserted `/` separators. All fixed; `GOOS=windows go vet` clean.

Verified (2026-11-04, local macOS arm64): `make check` + `make race` green.
