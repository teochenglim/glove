## Surface verification (2026-11-07 — re-verify on implementation day, §11 rule)

Read from the aaif-goose repo: issue #8742 (pre-tool-call governance proposal, closed as completed) implemented via PRs #9093 (hooks lifecycle) + #9304 (blocking PreToolUse) + #9468 (Stop-hook blocking), plus the hooks documentation.

- **Plugins**, not config.yaml: `~/.agents/plugins/<name>/hooks/hooks.json` (user) or `<project>/.agents/plugins/<name>/…`; disable via `disabledPlugins` in `~/.config/goose/settings.json`.
- **Rule shape**: `hooks` → `PreToolUse` → rules with optional regex `matcher` over the tool name; actions `{type: "command", command, timeout (default 30s), on_failure}`; command runs via `sh -c`.
- **Wire**: JSON on stdin — always `event`, `session_id`; conditionally `tool_name`, `tool_input`, `working_dir`, `tool_call_id`; built-ins: `shell`→`command`+`timeout_secs`, `write`→`path`+`content`, `edit`→`path`+`before`+`after`, `read_image`→`source`, `tree`→`path`.
- **Decisions**: block via stdout `{"decision":"block","reason":"…"}` (any exit) or exit 2 (reason from stderr); allow via exit 0 + empty stdout or `{"decision":"allow"}`; **anything else = no decision** (stray stdout, malformed/truncated JSON, non-UTF-8, timeout, spawn error — logged, tool proceeds). Denied calls surface as "Tool call denied by policy hook `<plugin>`: <reason>."
- **Fail-open default**; `on_failure: "block"` on a PreToolUse action closes it (timeouts/errors block) — never overrides an explicit denial or clean allow; **invalid values make goose skip the plugin's entire hooks.json with a warning**; invalid matcher regex skips only that rule.

## Scope notes (pre-implementation — written when built, red tests first)

- **Pure Go adapter — no TS shim.** Goose's hook is a native blocking surface; `internal/adapter/goose.go` fits the frozen §5.1 interface exactly (`ParseHookInput`/`RenderVerdict`/install/uninstall/status). It is structurally the *cleanest* enforcement adapter in the matrix: the vendor not only permits blocking, it offers `on_failure: "block"`.
- **Fail-closed posture (the first-class part):** `on_failure: "block"` + a tightened `timeout` means a hung, crashed, or slow glove hook blocks the tool call instead of waving it through — strictly stronger than codex (fail-open on timeout), gemini (fail-open on non-JSON stdout), and the claude/kilo/cursor shims (glove's own one-shot guarantee). glove still bounds itself per §6 (every other exit is a failure) and prints JSON-only stdout (the stray-stdout trap is gemini's lesson, applied here from day one).
- **Review → deny, loudly.** Goose's hook vocabulary has no ask; the tighten-only rule (ADR 1) renders review as deny exactly as cursor/gemini do. The docs page states it as a property of goose, not a glove choice — and points users at goose's own permission prompts as the complementary approval layer (glove's deny is the hard floor, goose's prompt is the day-to-day approval UX).
- **Install surface discipline:** glove writes only `~/.agents/plugins/glove/` (its own plugin dir) — never another plugin's files (the `~/.agents/plugins/` namespace is shared ground; uninstall removes exactly what install wrote, idempotently, conformance-pinned). `${PLUGIN_ROOT}` is not used; the hooks.json carries the absolute glove binary path.
- **Doctor health:** plugin dir present, hooks.json parses, rule intact (`on_failure: "block"` still set — its absence is the cursor-`failClosed`-style UNHEALTHY signal), `glove` binary on PATH, goose not listing the plugin in `disabledPlugins`.
- **Audit:** `agent: "goose"`, `session_id` from the payload (correlation works out of the box), tool name passthrough (`shell`/`write`/… and MCP names), input hash over the raw `tool_input`.
- **Open question to close on implementation day:** whether subagent tool calls emit `PreToolUse` today (the docs note `SubagentStart/Stop` are never emitted; tool-level coverage may differ) — the answer lands in `docs/install/goose.md` and the release file's Limits, honestly.
- **Positioning note from the verification pass:** the #8742 thread's own prior-art comparison (a deterministic rule hook with allow/deny/ask, fail-safe, <15ms, audit log) describes glove's Layer 0+1 exactly — goose users get that plus Layer 2, correlation, and the SIEM trail.
- **Dependencies:** none expected — no new crates/JS packages; the adapter is stdlib JSON + the existing engine.
- **Tests above are the plan** (house naming, ≥ 2 per AC); none exist yet — the status stays `planned` until the release checklist ticks, per `scripts/ac-map.sh`.
