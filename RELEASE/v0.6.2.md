## Built

- **Stress split (policy change, maintainer call)**: the load- and timing-heavy tests — §8 budgets, the 10k-query gate (335ms on a 2-vCPU macos runner that a laptop passes at ~50ms), accelerated soak, 5-target cross-compile, artifact roundtrip — moved behind `GLOVE_STRESS=1` via the new **`make stress`** target (packages serial, `-p 1`: the first parallel run failed its own bench by competing with the cross-compile builds). CI keeps the fast deterministic suite. PRD §8's gate column now says `make stress` release gate for the timing rows; the AGENTS.md release checklist gained `make stress`; `benchmarks/README.md` records the runner measurements (windows runner spawn: 57.1ms median cold start — a platform fact, documented, not gated).
- **Windows fixes**: `.gitattributes` pins the shim goldens byte-stable (`-text`) and the golden compare is CRLF-tolerant; `USERPROFILE` is passed to exec'd processes in the fresh-HOME flow and soak tests (`os.UserHomeDir` reads it on Windows).

Verified (2026-11-04, local macOS arm64): `make check` (fast — stress skips) + `make race` + `make stress` green; `GOOS=windows go vet` clean.

## Limits

- **Shipped half-applied — the honest post-mortem:** the fix script for the windows lane aborted mid-way and only part of it landed. `matrixTestEnv` never got the `USERPROFILE` line (so the in-process matrix tests still resolved to the runner's real profile), and the golden compare normalized only the golden side while the CRLF actually came from the rendered shim via the `go:embed`'ed template. The v0.6.2 CI run exposed both; the v0.6.3 record carries the real fixes. Lesson now applied: verify the fixes are in the tree (not just that tests pass on an OS where the paths never execute).
